# Ghostty では、ctrl+q ctrl+w が作業台の画面の分割を作り、そこへ移る

[ADR-0014](0014-workbench-shows-in-a-screen-the-user-opens.md) の「whatnext は端末のアプリを操作しない」を、Ghostty で押した `ctrl+q ctrl+w` と一覧の `w` に限って改める。作業台の画面を専用の tmux の2つ目のクライアントとして映すこと、中身の切り替えを tmux の `switch-client` で行うことは、ADR-0014 のまま変えない。サイクル7のあとに、利用者の依頼で決めた（2026-10-02）。

利用者は、作業台を作るたびに `cmd+d` で分割して `whatnext workbench` を打つ手間を省き、`ctrl+q ctrl+w` を押せば作業台の画面まで開いた状態になることを望んだ。何度押しても同じ形になる（すでに分割があれば移るだけ）ことも求めた。

そこで、Ghostty（1.3 の AppleScript）で押したときは次のようにする。

- 作業台の画面がつながっていれば、それを映している Ghostty の分割へフォーカスを移す。分割は増やさない。
- つながっていなければ、押した分割を右に分割し、そこで作業台の画面を開いてフォーカスを移す。押したタブに作業台の画面でない分割（ふだんのシェルなど）があっても、それは使わずに新しく分割する。
- 作業台がなければ、今までどおり作ってから上の動きをする。
- Ghostty でないとき、Ghostty が前面にないとき、AppleScript が失敗したときは、今までどおり案内を出すだけにする。

## Considered Options

- **押したタブにある別の分割を使い、そこへ `whatnext workbench` を打ち込む**：分割が増えない。ただし、その分割で vim やサーバが動いていたり、シェルに打ちかけの行があったりすると、そこへ文字が入ってしまう。Ghostty の AppleScript からは、分割がシェルの入力待ちかどうかを確かめられない。利用者は、新しく分割する案を選んだ。
- **ADR-0014 のまま、whatnext は端末を操作しない**：Ghostty 専用の動きを持たずに済み、macOS の自動操作の許可も求めない。ただし、作業台を開くたびに利用者が分割と起動を手で行う。
- **ADR-0014 で退けた「セッションを移るたびに分割の中身を差し替える」形**：採らない。分割を作るのは一度だけで、中身の切り替えは今までどおり tmux が行う。ADR-0014 が退けた理由のうち、この点は今回の形に当たらない。

## Consequences

- whatnext に Ghostty 専用の動きが1つ入る。ほかの端末では `ctrl+q ctrl+w` の動きは変わらない。
- 初めて押したときに、macOS が「Ghostty の操作」の許可を求めることがある。
- whatnext は、作業台の画面を映している Ghostty の分割を、端末のタイトルで見分ける。作業台のセッション（`sh-<id>` と案内のセッション）だけ tmux の `set-titles` を on にして、タイトルを `whatnext workbench` にする。`whatnext workbench` は終わるときにタイトルを消す。
- whatnext が作った分割は、作業台の画面が終わる（whatnext を終了する、別の端末で作業台の画面を開き直す）と閉じる。
- 一覧の `w` も、`ctrl+q ctrl+w` と同じく分割を作り、そこへ移る。当初は「whatnext の画面の中の操作で、移る先の分割を決める必要がない」として分割を作らなかったが、一覧で `w` を押しても作業台の画面が開かず、attach しているときと動きが食い違うため、利用者の依頼で揃えた（2026-10-02）。分割するのは whatnext の画面の分割である。
- 案内の `Enter` は、分割を作らない。作業台の画面の中の操作で、作業台の画面はすでに開いているため。

## タブで開くキーを足した（2026-11-17）

利用者は、claude の画面を広く保つことを望んだ。右に分割すると、claude の画面は半分の幅になる。そこで、`ctrl+q ctrl+t` と一覧の `t` を足し、Ghostty では押したウィンドウの新しいタブで作業台の画面を開くようにした。`ctrl+q ctrl+w` と一覧の `w` は、今までどおり右に分割する。Ghostty に限って端末を操作すること、何度押しても同じ形になること（開いていれば、どのキーでもそこへ移るだけ）、タイトルで見分けることは変えない。

- **キーで押し分ける（採った）**：並べて見たい場面と、claude の画面を広く使いたい場面を、押すたびに選べる。キーが1つ増える。
- **タブだけにする**：いったんこの形で実装したが、利用者は分割も残すことを求めた。
- **起動時のフラグか環境変数で決める**：キーは増えないが、途中で変えるには起動し直す。
- **右 1/3 に分割する**：同時に見えるが、作業台の画面が 1/3 の幅になる。Ghostty の `split` には比率の引数がなく、半分に割ったあと `resize_split` でピクセル単位に境界を動かすことになり、幅の計算に誤差が出る。実機では確かめていない。

タブでは、claude の画面と作業台の画面は同時には見えず、作業台の画面の追従は、タブを切り替えたときに分かる。作業台の画面で一覧に戻るキー（メモ、停止、新規、待ち先、一覧）を押したときは、入力欄や確認が隠れたタブで開くのを避けるため、whatnext の画面のタブへフォーカスを移す（利用者の判断。2026-11-17）。隣の分割で見えているときは移さない。whatnext が Ghostty を操作する場面が、作業台の画面を開くキーのほかに1つ増える。

## 見直す条件

- Ghostty の AppleScript の辞書が変わったとき（1.3.1 で確かめた。`new tab` は 1.4.0 で確かめた）。
- 利用者が Ghostty 以外の端末に移り、同じ動きを求めたとき。
